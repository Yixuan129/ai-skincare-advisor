# 用户研究如何进入产品设计

本说明根据项目现有研究文档、原始评论文件的结构复核及当前源码整理。它展示研究方法与设计理由，不把设计假设写成已经验证的产品效果。

## 研究输入

| 材料 | 在项目中的用途 | 局限 |
|---|---|---|
| 问卷 | 了解选品、用法、信任与预算相关问题 | 现有研究文档记录 65 份答卷；存在跳题与样本结构偏差。本次仓库整理未重新核算所有问卷题目，不发布个人答卷 |
| 访谈 | 理解使用经历、疑虑与决策背景 | 现有研究文档记录四份访谈；样本有限，不用于估计人群比例 |
| 抖音评论 | 找到用户实际提问形式，构建设计与测试线索 | 8 个定向视频、5 个采集关键词；不代表平台整体 |
| 小红书阶段分析 | 补充使用过程中的问题线索 | 本仓库未重新复核采集表和主题编码，不引用平台需求占比 |
| 产品资料 | 建立本地产品编号、字段与规则匹配基础 | 文件提取不等于完成公开来源核验 |

## 评论数据质量

2026-11-10 对现有 CSV 进行结构复核：

| 口径 | 数量 |
|---|---:|
| 原始记录 | 1,300 |
| 视频 URL | 8 |
| 采集关键词 | 5 |
| 不同原文文本 | 1,120 |
| 同视频同文合并后的文本单元 | 1,121 |

完全同文可能来自不同账号，不能仅凭同文判定无效采集。文本单元也不能解释为独立用户。项目报告中的关键词规则只用于候选检索，一条可命中多类；没有完成全量语义编码与双人复核，因此不据此排列市场需求。

## 从问题到功能

以下为研究所提示的设计方向与当前实现的对应关系，属于设计推理，不是因果检验。

| 问题线索 | 产品决策 | 实现位置 |
|---|---|---|
| 选购与已有产品的用法疑问并存 | 区分选品与使用任务 | `src/qa/model.ts`、`src/pages/QuizPage.tsx` |
| 产品版本或名称不明确 | 先匹配产品，信息不足时保留追问分支 | `src/rules/engine.ts` |
| 当前不适不能与历史敏感混为一谈 | 分开记录，并为当前不适设置分流 | `src/qa/model.ts`、`src/rules/engine.ts` |
| 预算与成分经验影响选择 | 用显式规则筛选，并展示结果理由 | `src/rules/engine.ts`、`src/rules/present.ts` |
| 用户需要直观进入相关产品 | 独立面部区域入口 | `src/pages/FaceMapPage.tsx` |
| 看完详情仍需继续比较 | 保留结果返回路径，支持对比与保存 | `src/products/navigation.ts`、`src/saved/storage.ts` |

## 下一步验证

用模拟案例验证规则和流程之后，仍需真实可用性测试来检验理解程度、完成任务情况和信任边界。未完成的工作包括主题人工复核、产品资料核验、用户任务测试及个人与团队贡献归属确认。
